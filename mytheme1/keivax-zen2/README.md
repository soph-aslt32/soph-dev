# Keivax-zen2

## Rule

変更内容は必ずこのREADMEに反映すること．

## Prompt

- 使用できる色はColorPaletteからのみ選択可能（透明度の変更は可能）
- 全てのセクションの枠線が透明で，全体が一色で統一感がある
- 背景色は暗い色で，微妙に寒色寄りの方がよい
- 選択，マウスホバー等で，特定のものを選択しようとしているときは，わかりやすく色が変わる．（読みづらくなったりするのはNG）
- プログラム中の文字列が，クラス，関数，引数，ローカル変数，グローバル変数，外部ライブラリ，etc...などで，文字の色，下線，イタリック，太字，等を用いて一目で区別がつくような配色とフォント分けが好ましい

## Prompt Add1

- プログラム中で変数などをクリックして，同じものが使用されている箇所がハイライトされる際に，より目立つ色にしたい
- クラス，関数，引数，ローカル変数，グローバル変数，外部ライブラリを，文字の色，下線で強調，イタリック，太字などを用いてより一目で区別できるようにしたい．特に色の差に気を付けてほしい．
- ファイル中に，警告，エラー，未コミットの内容，git管理対象外のファイル，があるときのファイル名の文字色の差をつけてほしい．

## Prompt Add2

- 背景色は，エディタ部分，サイドパネル部分，ターミナル部分，ウィンドウのタブ部分，どこでも厳密に同じ色を使うこと

## Prompt Add3

- クラス，関数，引数，ローカル変数，グローバル変数，外部ライブラリなどの，プログラム中に登場する重要な要素や型には，白色系の色を使わずに，何らかの色を採用すること．

## Prompt Add4

- (特にPythonで顕著)文字列，Docstringコメントなどで，似通った色が使用されている．コメント等プログラムの動作に関係ないものは配色や透明度を活用して読めるが，目立たないようにしつつ，プログラム中に似通った色が可能な限り登場しにくいように，配色を調整したい．

## Prompt Add5

- tokencolorsやsemantictokencolorsなどで指定されている，各種文字色について，特にプログラム中に登場するものについて，似通った色の採用を避けたい．現状でも，文字列，関数名，ローカル変数が，黄色や黄緑系統に固まっている．それ以外の項目も含めて，プログラム実装の観点から全体を見直し，区別しやすい配色に調整したい．
