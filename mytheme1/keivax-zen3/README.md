# Keivax-zen3

modernUI + `"workbench.experimental.modernUIEditorTabStyle": "pill"` を前提にしたカラーテーマです．
`"connected"`の場合の見た目については現状保守されていません．

APIリファレンス <https://code.visualstudio.com/api/references/theme-color>

## Prompt

- 使用できる色はNewColorPaletteからのみ選択可能（透明度の変更は可能）
- 全てのセクションの枠線が透明で，全体が一色で統一感がある
- 背景色は暗い色で，微妙に寒色寄りの方がよい
- 選択，マウスホバー等で，特定のものを選択しようとしているときは，わかりやすく色が変わる．（読みづらくなったりするのはNG）
- プログラム中の文字列が，クラス，関数，引数，ローカル変数，グローバル変数，外部ライブラリ，etc...などで，文字の色，下線，イタリック，太字，等を用いて一目で区別がつくような配色とフォント分けが好ましい

## Prompt Add1

- プログラム中で変数などをクリックして，同じものが使用されている箇所がハイライトされる際に，より目立つ色にしたい
- クラス，関数，引数，ローカル変数，グローバル変数，外部ライブラリを，文字の色，下線で強調，イタリック，太字などを用いてより一目で区別できるようにしたい．特に色の差に気を付けてほしい．
- ファイル中に，警告，エラー，未コミットの内容，git管理対象外のファイル，があるときのファイル名の文字色の差をつけてほしい．

## Prompt Add2

- 背景色は，エディタ部分，サイドパネル部分，ターミナル部分，ウィンドウのタブ部分，どこでも厳密に同じ色を使うこと

## Prompt Add3

- クラス，関数，引数，ローカル変数，グローバル変数，外部ライブラリなどの，プログラム中に登場する重要な要素や型には，白色系の色を使わずに，何らかの色を採用すること．

## Prompt Add4

- (特にPythonで顕著)文字列，Docstringコメントなどで，似通った色が使用されている．コメント等プログラムの動作に関係ないものは配色や透明度を活用して読めるが，目立たないようにしつつ，プログラム中に似通った色が可能な限り登場しにくいように，配色を調整したい．

## Prompt Add5

- tokencolorsやsemantictokencolorsなどで指定されている，各種文字色について，特にプログラム中に登場するものについて，似通った色の採用を避けたい．現状でも，文字列，関数名，ローカル変数が，黄色や黄緑系統に固まっている．それ以外の項目も含めて，プログラム実装の観点から全体を見直し，区別しやすい配色に調整したい．

## Prompt Add6

- ルーラー部分に表示される色，変更・追加・削除された行をハイライトする色，警告の色，エラーの色，変数選択時のハイライト色と対応するルーラーハイライト色，について，似通った色の採用を避けたい．警告は黄色系，エラーは赤色系，それ以外は赤色系でも黄色系でもないうえに，互いに見分けがつきやすい色，が望ましい．（当然，例えば警告が含まれるファイルは，タブ上でのファイル名部分も同じ色に，なるため，タブ上での見分けも付きやすくなる．）
  - タブ上での各ファイルの変更が含まれるなどによるハイライト表示をする際に，ファイルの文字部分の色を変更するだけでなく，タブ部分の背景色を，各要素に対応するハイライトなどにできるのであれば，それらの工夫を盛り込んでもよい．

## Prompt zen3 1

- 色は必ずNewColorPaletteから選ぶ
- 背景色以外には青系の採用率を増やす
- 本項目の要求以外を優先しつつも，目に優しいカラーテーマを目指す
- ユーザーからの指示を「## Prompt zen3 N」という形で追加していく

## Prompt zen3 2

- `themes/keivax-zen3-theme.json` のキー構成を引き継ぎ，色は置換ではなく本 README の要求に合わせて NewColorPalette から新たに割り当て，`themes/keivax-zen3-alpha-theme.json` に出力する
- 背景は `#1e2323` に統一する．サジェスト・ホバー・メニュー・通知なども同色にして，影のみで分離する
- エラー `#dd2a57`・警告 `#fcb346` は診断専用とし，シンタックスでは使わない
- `build_alpha.py` で生成し，`validate_alpha.py` と `check_palette.py` で検証する

## Prompt zen3 3

- 非アクティブ時のアイコン・行番号・パネルのタブ文字などが灰色や暖色に見える．画面全体を寒色系で統一する
- 非アクティブなタブのファイル名が暗い．選択中のタブの背景や，エクスプローラーで選択中の行を，もう少し目立たせる
- Git 装飾（ファイル名の色）は寒色のコンセプトから外れてもよい．変更・追加があったファイルを暗い色にしない．未追跡が目立たないのは好み
- 色の見分けにくさに配慮し，色相の違いだけに頼らず明度差も付ける
- 背景色を含む大胆な方針転換も可．比較用に青紫寄りの背景（`#201d33`）のテーマ「Keivax-zen3 Blue」を並置する

## Prompt zen3 4

- 標準の背景は青紫寄りの `#201d33`（Keivax-zen3 Blue）にする
- Git 装飾色は白・黒・灰色系をやめ，目立つ色にする．警告（黄色系）・エラー（赤色系）と競合しないこと．変更は一般にどの色で表すかも参考にし，寒色のコンセプトから外れてもよい
- 青紫の背景だと，UI（ステータスバーなど）・GitHub Copilot チャットの文字・エクスプローラーの非アクティブなファイルが目立たなさすぎるので調整する
- エディタで現在行の行番号を，そうでない行番号と区別しやすくする
- 全体を精査して改善案を出す．vscode-theme スキルの一般的な指針（コントラストを抑える，アクセントを絞るなど）から多少逸脱してよい

## Prompt zen3 5

- UI の文字色（エクスプローラーのファイル名・ステータスバー・サイドバー）は，見やすさより寒色の美しさを重視し，灰青 `#979ac4` に戻す．色はパレット内から選ぶ
- Git 装飾: 無視ファイルは灰色系にする．変更はもっと明るい色にする
- 灰青の文字が見づらい場合に備え，背景をより深くした比較用テーマ「Keivax-zen3 Deep」（`#0f0514`）を並置する

## Prompt zen3 6

- 透明度の変更は文字色を含めて可
- 背景は Deep ではなく標準の `#201d33` を採用する（Deep は削除）
- Git 装飾で変更と追加は別の色にする．明るいピンクなど，パレットから使えるものを再検討する

## Prompt zen3 7

- `colors` の設定をレビューし，次の2点を修正する
  - 選択・ハイライト・タブの背景を，明るさを抑えた濃い色（縁取りで目立たせる）にして，どの文字色の上でも読めるようにする
  - ボタンのホバー背景・エラーの文字色・ターミナルの黒と明るい黒を直す
- 保留: 未設定キー（`chat.*` など205個）の追加，定数・コメントの整理，カーソル色・入力欄の薄い文字の調整

## Prompt zen3 8

- コードの色の系統が多すぎるので減らし，頻出する要素はテーマのコンセプト（寒色）に寄せる．登場が少なくて目立たせたい要素だけを目立つ色（マゼンタ）にする
- ローカル変数と引数（関数に渡される変数）は同じ色にして，**引数の全使用箇所に下線**を付けて区別する
- 代入・変更は書式では示さず，変数選択時の読取／書込ハイライトで見せる
- 太字は宣言，斜体は自分のコードではないもの（外部ライブラリ・コメント），下線は引数，取り消し線は非推奨に限る．制御構文の太字は外す
- 注意色（マゼンタ）の対象は，グローバル変数・定数と `TODO` / `FIXME` などとする（追加するトークンは実機で確認しながら増やす）
- コンセプトに合うと判断すれば，ほかの配色も変えてよい
