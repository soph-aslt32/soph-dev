# keivax-zen3

VS Code カラーテーマ（modernUI + `"pill"` タブ前提）．要求仕様は `README.md` が正で，`## Prompt ...` の積み上げで管理する．

## 構成と編集ルール

- `themes/keivax-zen3-theme.json` は元テーマ．alpha のキー構成の参照元なので編集しない．
- `themes/keivax-zen3-alpha-theme.json` は `build_alpha.py` の生成物（`package.json` が参照）．直接編集せず，`build_alpha.py` の `COLORS_SPEC` / `TOKEN_SETTINGS` / `SEMANTIC_SETTINGS` を編集して再生成する．
- 背景は `#201d33`（青紫寄り）で確定．比較のうえ `#1e2323` と `#0f0514` は不採用．背景違いを見比べたいときは `VARIANTS` にエントリ（出力ファイルと背景色）を追加し，`package.json` にも登録する．
- 色は README の NewColorPalette のみ．透明度の付加は文字色を含めて可（ユーザー確認済み）．`#rrggbb` の直書きは避け，`build_alpha.py` 冒頭の役割名定数を使う．新しい色が必要ならパレット内から定数を追加する．
- 元JSONのキー・`tokenColors` の name/scope・順序は変えない（`validate_alpha.py` が検査する）．
- ユーザーからの新しい指示は README に `## Prompt zen3 N` として追記する．

## 変更後の検証

変更のたびに次の順で実行する（いずれも引数なしで alpha が対象．比較版を作った場合はファイルを引数に渡す）．

1. `python build_alpha.py`
2. `python check_palette.py`
3. `python validate_alpha.py`

目視確認は F5（`Extension` 起動構成）で開発ホストを開き，`sandbox.py` と `sandbox.rs` を見る．トークンの色の原因は `Developer: Inspect Editor Tokens and Scopes` で確認する．

## 設計方針（合意済み）

- 背景は `#201d33` に厳密統一する．サジェスト・ホバー・メニュー・通知などのポップアップも同色にし，`widget.shadow` などの影のみで分離する．
- 枠線は透明が基本．フォーカス・アクティブ表示・入力欄・ハイライト枠など機能的なものだけ残す．
- エラー `#dd2a57`・警告 `#fcb346` は診断専用．シンタックスでは使わない．
- ルーラー・ガター・ハイライト・ファイル名の色は，赤系と黄系を避けて互いに区別できるようにする（追加=緑，変更=青，削除=紫）．
- コードのトークン色は `build_alpha.py` の `Roles`（役割の色）で決め，直接 `#rrggbb` やパレット定数を `token_settings` / `semantic_settings` に書かない．標準は `ROLES_MAIN`: キーワード・`self`・デコレータ=`BLUE`，演算子・句読点=`MUTED`，変数（ローカル・引数・プロパティ）=`FG2`，関数=`ROSE`，型=`PURP`，値（文字列・数値・正規表現・`None`/`True`/`False`）=`GREEN`，コメント・Docstring=`DIM`，注意色（グローバル/定数など希少で重要なもの）=`MAG`．赤は診断専用なので注意色に使わない．
- 外部ライブラリ/ビルトインは専用の色を持たず，種類の色の斜体で表す（関数色の斜体，型色の斜体，変数色の斜体）．
- エディタ部分の文字色には淡い色を使ってよい（ユーザー確認済み）．ただし**型と関数の名前は淡い色にしない**．色は寒色が主で，ピンクまで使ってよい．
- 主要3者（型・関数・変数）は，冷色〜ピンク域の他のパレット色と比べて最良の組み合わせで確定済み（最小距離 11.6）．色を変えるときは，この3者が近くならないことを `validate_alpha.py` で確認する．演算子は記号なので他の色と近くてもよい．
- 配色案を見比べたいときは，`dataclasses.replace(ROLES_MAIN, ...)`（トークン色）や `dataclasses.replace(SURFACES_MAIN, ...)`（選択・ホバーなど面の色）で比較用を作り，`VARIANTS` と `package.json` に足す．決まったら採用案を `ROLES_MAIN` / `SURFACES_MAIN` にし，比較用を `VARIANTS`・`package.json`・`themes/` から削除する．
- 選択・ホバー・検索一致・現在行・上のバーのホバーなど面の色は `Surfaces`（割り当て表では `S_*`）で決め，パレット定数を割り当て表に直接書かない．標準は `SURFACES_MAIN`（下の「選択・ホバー」の項）．
- 括弧の入れ子の色（`BRACKETS`）は別途設定済みなので，トークン色の変更に合わせて変えない．
- 文字スタイルの意味は1つに限る．太字=宣言（`*.declaration`），斜体=自分のコードではないもの（外部由来・コメント），下線=引数（変数と同色なので**全使用箇所**に付ける），取り消し線=非推奨．代入・変更はスタイルで示さず，読取／書込ハイライトに任せる．
- シンボルアイコン・デバッグ式の色は `R_TYPE` `R_FUNCTION` などの役割名で書き，トークン色と連動させる．
- 元テーマに無いトークン項目は `EXTRA_TOKEN_COLORS` で末尾に足す（元の項目の name/scope・順序は変えない）．スコープ名は実機の `Developer: Inspect Editor Tokens and Scopes` で確認してから足す．
- 役割ごとの色の近さは `validate_alpha.py` の距離（OKLab x100）で確認する．
- 重要なコード上の要素に白系の色は使わない．
- 非アクティブ・静かな文字や線は寒色の灰（`DIM` / `MUTED` = `FG2` の透明度違い）にする．暖色寄りの灰は使わない．暖灰 `DOC` は Docstring 専用（コメント・キーワードと色相で区別するため）．
- ユーザーは色の違いを見分けにくい特性がある．色相の違いだけに頼らず，明度差・太字/斜体/下線・バッジなどの併用を前提に設計する．
- Git 装飾（ファイル名の色）は視認性を優先し，コンセプトから外れてもよい．白・黒系は使わず鮮やかな色にし（無視ファイルだけは灰色系），警告（琥珀）・エラー（バラ色）と競合する黄・赤系は避ける．変更（作業ツリー）=`ROSE`（明るいピンク），追加・名前変更・ステージ済み変更=淡緑，未追跡=オリーブ，削除=`PURP`，競合=`MAG`，無視=`DIM`．エラーのファイル名は赤 `ERR`（`ROSE` とは明るさで区別）．変更と追加は別の色にする（同色にしない）．エクスプローラーの基本文字は `CHROME`．
- UI の文字（エクスプローラー・サイドバー・ステータスバー・非アクティブなタブなど）は `CHROME`（= `FG2` 灰青）．パレットで最も明るい寒色．明るさの調整は `CHROME` の差し替えで行う．
- 選択・ホバー（リスト・タブ・エディタ本文の選択範囲・ツールバー）は `BLUE_M`（中間の青）をほぼ不透明のまま使う（`SURFACES_MAIN`．ユーザーが実機で比較して採用）．アクティブ=0.85，フォーカス行=0.75，非アクティブ=0.65，同じ文字列の強調=0.55，ホバー=0.55，エディタ上のホバー強調=0.33（以前「きつい」と指摘があったので薄い）．**選択上のコード色（コメント・型・キーワード）のコントラストは 3.0 を下回る**（最低 1.6）が，ユーザーが了承済み．`validate_alpha.py` の「ハイライト上のコード色」「ファイル名の色 × 選択行/タブ背景」の指摘は選択・ホバーについては想定内として扱う．
- 単語ハイライト・差分・検索一致など，選択・ホバー以外のハイライトの背景は，明るさを抑えた濃い色（`DEEP_WINE` `DEEP_GREEN` `DEEP_VIOLET` `DEEP_PURPLE`）にし，目立たせたい場合は明るい縁取り（`border`）を付ける．これらは文字が読めること（`validate_alpha.py` の「ハイライト上のコード色」が 3.0 以上）を保つ．
- 同一変数ハイライトの塗りは読取（`wordHighlight`）・書込（`wordHighlightStrong`）とも `DEEP_WINE` で共通にし，区別は縁取りだけで行う（読取=`MAG`，書込=`PALEGREEN`．縁取りは文字の読みやすさに影響しない）．縁取りの組は，互いの距離・明るさの差が大きく，塗りと外側の背景の両方から離れた色を選ぶ（色相だけの差になる組は避ける）．ルーラーの印も縁取りと同じ色にする．
- `BLUE_M` はボタン・バッジの背景と，選択・ホバーの塗りに使う．ボタン等のホバー背景は `VIOLET_B`（`FG` の文字が 4.5 以上）．
- 上のバー（メニュー・コマンドセンター・ステータスバー）のホバーは塗りをなくし，文字の明暗（`CHROME` → `FG`）で示す．タイトルバーの普段の文字は `CHROME`，ウィンドウが非アクティブなときは `DIM`．
- エラーの色は，文字（入力欄の検証・デバッグコンソール等）は `ROSE`，線・アイコン・ファイル名は `ERR`．

## コミット規約

- 変更のたびにコミットする．複数の変更をまとめない．
- `main` に直接コミットする．push はユーザーの指示があるまで行わない．
- 書式は `[add]` / `[update]` / `[WIP]` + 説明（日本語可）．例: `[update]背景色を #1e2323 に統一`
- コミットメッセージに Claude 関係の記述（`Co-Authored-By` など）は書かない．
- 生成物（alpha JSON）は，生成元スクリプトの変更と同じコミットに含める．
- `git add` はファイル名を明示する．ワークスペース外の未追跡ファイル（`../keivax-zen2/hoge.md` など）はコミットしない．
